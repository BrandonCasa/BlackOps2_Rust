# Black Ops II Zombies: Origins in Rust

A personal-use Rust reimplementation of Origins, pursuing faithful behavior,
visuals, and reusable Zombies architecture through evidence from a licensed local
copy of the original game. Bevy is the selected engine, ECS, rendering, and
application foundation.

The default application runs a minimal headless Bevy lifecycle smoke check.
Separate inspectors read metadata and diagnostic snapshots; a Bevy diagnostic
tool adapts source snapshot geometry into canonical Bevy coordinates for external offscreen images or
opens it in a window with diagnostic flight controls. A separate headless damage
demonstration applies ordered resolved impacts to an Origins-configured player
and ordinary actor, with coop revival and bleedout clocks. This boundary is
**APPROXIMATE**; scoped original health comparisons support resolved arithmetic,
while raw impact admission and final actor health remain unresolved. Overall gameplay and visual fidelity
remain **UNKNOWN**; envelope format understanding is **INVESTIGATING**.

Run `cargo run -p bo2-damage-life-state-demo --locked` for synthetic player downing,
actor death, ordered revival and timed bleedout/revival scenarios. See
[damage boundary and limits](docs/architecture/damage-life-state.md).
Raw hit policy and solo game-end behavior remain unimplemented; live coop timing
comparison remains pending.

Original assets stay external. Never commit, embed, or redistribute proprietary
assets, binaries, scripts, extracted content, generated dumps, or local installation
paths. Copy `config/local_assets.example.toml` to the ignored
`config/local_assets.toml` and replace its placeholders locally when an inspection
or asset-loading task needs configuration. The application does not consume it yet.

The workspace pins stable Rust 1.99.0 in `rust-toolchain.toml`, with Rust edition
2024, rustfmt and Clippy. Install [Rust using rustup](https://rust-lang.github.io/rustup/installation/index.html)
and the native build tools for your platform; Windows requires the MSVC linker
and Windows SDK. Bevy is pinned to released version 0.19.1 with default features
disabled and only `std` explicitly enabled. Compatibility evidence and the
headless boundary are recorded in the [Bevy decision](docs/adr/0001-bevy-foundation.md).
The diagnostic render tool locally enables the pinned engine's PBR/rendering
facilities; central umbrella defaults and the boot application remain unchanged.

```sh
cargo run -p bo2-boot -- --smoke
cargo metadata --no-deps --format-version 1
cargo test --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

The default invocation also runs the smoke check; `--help` describes the available
arguments. Bevy runs startup once, spawns a synthetic probe, updates it three times
through its ECS schedules, validates the result, and exits using `AppExit`.
Success prints `Smoke: PASS (startup=1, updates=3, probe_updates=3).` and returns
exit code 0. A failed check returns 1; unsupported arguments return 2. The count
and runner pause are development checks, not Origins timing or behavior.

`Cargo.lock` is generated by Cargo and retained. Actual validation results and
platform limits are recorded in the [build handoff](docs/handoffs/0003-bevy-build-foundation.md).

Inspect one explicitly selected external file using:

```sh
cargo run -p bo2-asset-inspector -- "<external input file>"
cargo run -p bo2-asset-inspector -- --help
```

The inspector supports only the [observed signed PC envelope subset](docs/reverse_engineering/0002-fastfile-envelope.md).
It reads a 12-byte discriminator, then completes at most 312 envelope bytes.
Output contains version, bounded name, total length, opaque ranges and a disk-stem
diagnostic; source paths and malformed raw fields are omitted. Authentication
remains unverified and the payload unread. A renamed file is diagnostic, not
corrupt. Exit codes are 0 for metadata success/help, 1 for input/inspection/output
failure and 2 for invalid arguments. The CLI does not load TOML or discover files.
See the [inspector handoff](docs/handoffs/0006-fastfile-envelope-inspector.md) for
tests, external sample checks and limits.

Inspect retained external brush geometry and exercise diagnostic segment queries:

```sh
cargo run -p bo2-map-inspector -- --brush "<external schema28 brush record>"
cargo run -p bo2-map-inspector -- --brush-collection "<external schema34 collection>"
```

The [collection boundary](docs/architecture/diagnostic-brush-collection.md) admits
every selected record, preserves source coefficients and reports unsupported
families and source-vertex discrepancies. The accepted Origins collection has
8,417 records, including 3,178 diagnostic zero-side axial hulls. These commands
emit bounded counts, segment probes and precision summaries without changing files.
Identity hashes are declarations until independently checked. Original runtime
ownership, player dimensions, masks and contact rules remain unresolved; these
queries are not yet integrated into player movement.

The collection report also runs three single-brush float32 moving point queries
per positive/zero-side representative using the
[recovered native contract](docs/architecture/moving-brush-trace.md). Their zero
extents/all-bits mask are explicit diagnostic inputs. Native runtime output
comparison and stationary/world traces remain unverified or unsupported.

Render a user-created asymmetric fixture, or one explicitly selected diagnostic
snapshot, to a **new** external directory:

```sh
cargo run -p bo2-geometry-viewer -- --check-gpu
cargo run -p bo2-geometry-viewer -- --synthetic --output "<new external directory>"
cargo run -p bo2-geometry-viewer -- --snapshot "<external snapshot>" --output "<new external directory>"
```

The [offscreen diagnostic](docs/architecture/diagnostic-geometry-render.md) emits
three 512x512 canonical-axis images (legacy raw-Z/raw-X/oblique filenames) with a neutral unlit solid and built-in
triangle-edge overlay. Positions adapt to Bevy space; indices, UVs, source metadata
and identity mesh Transform are retained.
These are chosen Bevy views; original orientation, units, visible side, camera,
materials and appearance remain unresolved. Use an independent 120-second
supervisor for GPU/driver calls. No original game or SDK capture is involved.

Inspect the geometry adapted to Bevy coordinates in a window with a diagnostic free camera:

```sh
cargo run -p bo2-geometry-viewer -- --synthetic --interactive
cargo run -p bo2-geometry-viewer -- --snapshot "<external snapshot>" --interactive
cargo run -p bo2-geometry-viewer -- --synthetic --interactive-smoke
```

W/S move forward/back, A/D strafe, E/Q move along Bevy world +Y/-Y, and arrow keys look.
Shift increases speed fivefold; Ctrl reduces it to one tenth. R resets and reframes
the bounds; Escape or window close exits. Speed is one bounds radius per second.
Runtime coordinates follow Bevy: +Y up and camera-local -Z forward. The shared
boundary adapter rotates source Z-up positions/vectors `(x,y,z)` to `(x,z,-y)`.
Both the map and textured scene use this adapter once; source files, triangle
winding, UVs and raw unit scale are retained. Source surface metadata bounds stay
in source space. Legacy offscreen `raw-*` filenames now contain canonical views.
The perspective camera, speed and flight behavior are diagnostic choices;
there is no collision or original player movement. Original fidelity remains UNKNOWN.
Interactive modes write no files. `--interactive --frames <64..600>` bounds updates;
`--interactive-smoke` defaults to 180 updates and exercises scripted Bevy keyboard
messages for movement/look/reset, GPU mesh/pipeline readiness and a foreground
window readback before exiting. This checks engine input integration, not physical
keyboard routing or original-game comparison. Use an independent 120-second
supervisor for bounded GPU/driver checks.
