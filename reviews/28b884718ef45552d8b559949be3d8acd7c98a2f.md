### ICE-1 — P1 — Hidden unused original tiles can absorb shots intended for the selected tiles

- Original code: `src/staff_puzzles.rs:156-161`; surrounding integration `src/environment/brushes.rs:123-135`, `src/environment/support.rs:48-83`. Original `assets/origins/game.json:1` contains `shootable:true` ownership for original-slot brushes with GUIDs `9ED8F211`, `75398A6B`, `DEC50AF2`, `B8B7583D`, `CB03521A`, and `A3577978`.
- Reference: `todo-audit-20261010/decompiled/t6/zm_tomb_quest_ice.gsc:85-105` deletes unused tiles. `game-prepare/entities/maps/mp/zm_tomb.d3dbsp.ents:3697-3749` defines the six original-slot tile brushes; `:3577-3623` defines the other six candidates.
- Trigger: randomization excludes an original-slot tile and relocates another selected tile into its slot. The excluded original is only hidden/disabled and retains its prebound `ShootableEnvironment`. Its unchanged native collider overlaps the newly selected tile. The shared hit selector directly raycasts every shootable collider and does not filter `ColliderDisabled` or visibility.
- Impact: an invisible unused brush can win the closest-hit selection. It has no `IceTile` on the first session, so `ice` ignores its hit while the projectile is consumed. Correct-looking shots can fail to advance the sequence, with behavior dependent on selection, ray, and equal-distance ordering. This is a concrete stale-target integration defect; a universal softlock is not asserted without a real-game run.
- Future correction: retire unused brushes from the shootable-target set as well as presentation/physics, and ensure each selected slot has only its live intended target. Preserve the original brush content.
- Status at cutoff: outstanding. No later bounded commit changes this setup, `support::cast`, brush ownership, or the asset pack.

### ICE-2 — P2 — Session restart resets logical progress but retains solved tile rotations

- Original code: `src/staff_puzzles.rs:40-41,145-161,186-192`; surrounding integration `src/session.rs:87-96` only despawns `SessionEntity` objects. Bound map brushes are not session entities (`src/environment/brushes.rs:112-137`).
- Reference: `todo-audit-20261010/decompiled/t6/zm_tomb_quest_ice.gsc:36-47,74-105,178-202` initializes tile sides and fresh selection, then controls explicit side state.
- Trigger: solve one or more tiles, end/reset the session without reloading the map, then start the next session. `setup_ice` changes selected translations but never restores their rotation, removes obsolete `IceTile` components, or clears old `ColliderDisabled` markers.
- Impact: the new `ice_remaining` set treats all chosen tiles as unsolved while reused brushes can still show their prior solved face. Each subsequent solve/reset adds another relative half-turn. The visual puzzle no longer corresponds consistently to the new logical puzzle; stale hidden targets from ICE-1 also accumulate previous setup state. The direct hit selector's disregard for `ColliderDisabled` means that marker alone does not prove shots stop working, so this finding does not rely on that claim.
- Future correction: restore each persistent brush's authored transform and puzzle components before randomization, or build disposable session instances from the preserved brush data. Initialize side state explicitly rather than accumulating relative rotations across sessions.
- Status at cutoff: outstanding; later bounded changes to `staff_puzzles.rs` only add Fire logic or expose module/items to upgrade integration.

### ICE-3 — P2 — Successful tile input becomes available before the native flip-and-settle interval

- Trigger: fire again 0.2-0.7 seconds after a correct tile hit, or watch/read the display during that interval.
- Impact: the draft accepts the next tile about half a second earlier and displays its value before the original animation completes. It changes the timing challenge and feedback sequence even though the wrong-shot lock has the recovered two-second duration.
- Future correction: represent the recovered flip duration and delayed display update as fixed-tick puzzle state; unlock successful inputs after flip completion plus 0.2 seconds. Animate the preserved brush rather than snapping it.
- Status at cutoff: outstanding; no later bounded commit changes `ice` timing.
