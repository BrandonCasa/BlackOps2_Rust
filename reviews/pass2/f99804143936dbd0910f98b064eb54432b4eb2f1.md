## Actionable correctness findings

### P2  -  Count completed normal-box uses at the source decision point

Trigger: repeatedly purchase the initial box or buy Fire Sale rolls. `src/stations.rs:177-181` increments `uses` before testing `<4`, `>=8` etc.; Fire Sale increments the same counter even though it suppresses the teddy draw. This allows the first teddy one normal roll early, forces the first relocation one roll early, and lets cheap temporary purchases advance normal relocation odds. `source/server-patch/maps/mp/zombies/_zm_magicbox.gsc:1120-1230` tests the prior completed-use count, protects the first four normal offers, forces the first move after eight prior uses, and excludes the Fire Sale branch from the normal movement progression.

Correction: keep normal relocation history separate from aggregate purchase statistics, make the teddy decision with the pre-increment normal count, and increment at the source offer/completion boundary. Preserve the one applicable random draw and no-teddy Fire Sale branch. Confidence high; current at endpoint.

### P2  -  Apply family exclusion and the Mark II rejection gate

Trigger: roll with either Ray Gun family owned, or roll Mark II without either. `src/stations.rs:117-125` excludes only each exact base/upgraded pair and gives Mark II an ordinary weight. `source/server-tomb/maps/mp/zm_tomb.gsc:1608-1637` excludes both Ray Gun families when either is owned and rejects an otherwise selected Mark II on `randomint(100) >= 33`. Draft permits simultaneous family ownership and overstates Mark II frequency; simply applying weight 33 to a flat table is not the same rejection sequence.

Correction: perform the source family predicate in the candidate/selection path and a rejection loop in the existing roll function, preserving the gate draw only when Mark II is selected. Confidence high; current at endpoint.

### P2  -  Power loss must terminate the deposited-gun lifecycle

Trigger: a generator shuts down during processing or while a gun awaits collection, then all six generators are restored before the old timer expires. `src/stations.rs:108-114,197-199` keeps ticking the deposit and only hides interaction under the power gate, permitting later collection. `source/server-patch/maps/mp/zombies/_zm_perks.gsc:682-718,833-850` ends the take watcher on `Pack_A_Punch_off` and destroys the world gun on blackout. The old deposit does not resume.

Correction: process the power transition in the station tick, cancel the deposit/world reward through one cleanup path, and make that boundary precede interaction acceptance. Confidence high; current at endpoint.

### P2  -  Deposit must own the short hand/action interruption

Trigger: deposit while another firearm remains available. `src/stations.rs:207-213` removes the weapon; `src/weapons.rs:287-295` cancels that action and immediately activates another slot, allowing immediate actions during the source knuckle-crack interval. `_zm_perks.gsc:858-912` sets drinking/action restrictions and disables weapon/offhand inputs during the action, restoring them on completion, downing or other termination.

Correction: add a short station interaction component integrated with the existing weapon-action restrictions, interrupt incompatible pending emissions once, and restore on normal/cancelled exits. Do not freeze unrelated ECS systems. Confidence high; current at endpoint.

### P3  -  Collecting a station reward should interrupt an ordinary reload

Trigger: reload while taking a box offer or processed PaP gun. `src/stations.rs:164,188-190,221` requires `WeaponAction::Ready` before calling `receive`, although the existing receive path permits cancelling/replacing reload. Source purchase gating (`_zm_magicbox.gsc:673-692`) excludes drinking, equipment/hacker/revive states rather than every gun reload; the reward pickup path handles the switch. Draft misses the offer and can expire it while the player reloads.

Correction: distinguish purchase/deposit eligibility from reward-take eligibility and let the existing receive operation cancel only its supported actions. Confidence high; current at endpoint.

### P2  -  Reject an unaffordable box use before consuming a weapon roll (additional finding)

Trigger: press use on the box with fewer than 950 points (or fewer than 10 in Fire Sale). `src/stations.rs:173-175` calls `roll`, advancing the shared session RNG, before `ledger.accept` rejects payment. A rejected action changes the next box result and any other shared gameplay randomness. Original purchasing checks funds before beginning the paid box selection; the source chest-purchase gate at `_zm_magicbox.gsc:457-478`, followed by box opening/randomization at `:487-515` and weapon selection at `:1117-1119` was compared with the native bounded RNG call chain above. This is observable as rejection-driven rerolling, even without requiring exact original PRNG state.

Correction: perform the pure affordability/eligibility check first, then atomically reserve payment and sample the accepted roll; if the candidate set is empty, reject without paying or sampling. Confidence high on draft rejection consumption, medium on exact source all-branch RNG parity. Current at endpoint. The separately introduced PaP attachment rejection-draw defect belongs to `reviews/pass2/308483475093fa3abd7cf3431182937bcae4e650.md`, not this finding.
