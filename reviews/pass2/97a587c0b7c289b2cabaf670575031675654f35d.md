## Actionable correctness findings

### P2 - Gate matching return frames by the first completed opening

Trigger: enter the Crazy Place through one element and activate another element's return. `src/portals.rs:33-36,122-130` creates and accepts every return target independently of its entrance history. `source/server-tomb/maps/mp/zm_tomb_teleporter.gsc:114-123,212-216` creates/shows the matching return frame only once that element first opens. Draft grants exit routes to elements not yet unlocked.

Correction: retain an element return-unlocked flag set on first source opening, and gate frame visibility/activation by it; keep temporary open timers separate from permanent unlock. Confidence high; current at endpoint.

### P2 - Separate opening interaction from passive portal traversal

Trigger: walk into an open portal without a fresh use press, or approach while prone. `src/portals.rs:73-78,113-130` requires aim cone, ray, new use press and ordinary inventory readiness for both entrance/return traversal. Source `zm_tomb_teleporter.gsc:185,231-275` uses a passive entrance/open-return radius and excludes prone/teleporting players; `source/server-tomb/maps/mp/zm_tomb_utility.gsc:825-840` confirms omitted use_trigger means passive radius. A separate use trigger opens the return frame at `zm_tomb_teleporter.gsc:122`.

Correction: keep gramophone/frame opening in Interactions, then perform open-portal occupancy/stance eligibility in a normal fixed-step travel system without taking InteractionFocus or consuming another use edge. Confidence high; current.

### P2 - Preserve the two-second transit and action ownership

Trigger: traverse and immediately move/fire/throw at the destination. `src/portals.rs:58-62,115-118,129-130` teleports instantly and merely starts a cooldown. Source `zm_tomb_teleporter.gsc:309-382` sets teleporting, disables offhands/weapons, freezes controls, moves/links into a separate image room, waits two seconds, then applies destination and restores actions. Draft changes arrival timing, allows destination attacks/movement during transit and exposes the body at a place it has not yet reached in the source.

Correction: add a short Transit component with destination pose/deadline and a shared temporary action lock; move to the existing transit-room representation or explicitly document an isolated protected transit approximation, then relocate/restore once. Clear velocity/platform/fall state at accepted transitions and handle terminal/session cancellation. Do not add a second movement engine. Confidence high; current; exact original network-frame fades are an unavoidable timing approximation unless implemented with existing presentation systems.

### P3 - Apply destination angles as well as position

Trigger: portal destinations face a different direction from entry. `src/portals.rs:58-62,115-116,129` and `src/portals/source.rs:14-25` retain only positions, preserving old yaw/pitch. Source `zm_tomb_teleporter.gsc:367-378` chooses a free destination struct and sets both origin and angles, corroborated by native `005e38f0`. Draft can point players into a wall/back toward the portal and changes their first shot/view after arrival.

Correction: retain authored arrival/return orientation in the existing source table and apply it with relocation at transit completion, clearing incompatible recoil/look deltas as appropriate. Confidence high; current.

### P2 - Return carried crystals on terminal loss, not entering last stand

Trigger: down with an uncrafted crystal and then revive. `src/crafting.rs:183-190` releases it whenever health is not Standing. Source `source/server-tomb/maps/mp/zombies/_zm_craftables.gsc:308-312` waits for `bled_out`, despite the function's downed-like name; its disconnect path is separate. `source/server-tomb/maps/mp/zm_tomb_craftables.gsc:544-556` then resets the crystal to its original plinth. Draft prematurely removes carried progress on a survivable down.

Correction: react to terminal bleedout/disconnect/session lifecycle messages with a once-only crystal release, retaining it through Downed/Reviving. Returning to the original plinth is correct for the crystal callback; replacing that with a generic death-position drop would introduce another mismatch. Confidence high; current.

### P3 - Wait for the crystal plinth/reveal sequence

Trigger: first traverse an element portal. `src/portals.rs:116-117` marks visited immediately and `src/crafting.rs:58-65,89-92` makes the crystal collectible immediately. `source/server-tomb/maps/mp/zm_tomb_main_quest.gsc:551-602` waits for matching traversal, moves the plinth for six seconds, requires a continuous one-second look, then reveals/rises/rotates the crystal. Draft permits early pickup and removes the discovery cue.

Correction: use per-element crystal emergence state/deadlines and continuous-look progress on the existing collectible entity, enabling its ordinary pickup only at the source reveal boundary. Bind original plinth/model/FX rather than authored replacements. Confidence high; current.
