## Actionable correctness findings

### P1 - Drain generators only while recapture zombies actually attack

Trigger: raiders are alive but emerging/travelling/blocked/lured away, or all current attackers have left while other raiders survive. `src/generators/raids.rs:45,62-73` drains whenever any raider is alive; the current target is excluded from restoration even when nobody attacks. Source `zm_tomb_capture_zones.gsc:1022-1074,1266-1299,1664-1676,1930-1940` requires completed approach, target matching and actual generator attack state, then restores at the source positive recapture rate when appropriate. Draft shuts generators down remotely with no opportunity to stop drainage by interruption.

Correction: persist an explicit attack substate in GeneratorAttacker updated by the ordinary AI arrival/melee path, count only valid attackers for that target, and apply source zero/drain/restore rates before shutdown. Confidence high; current at endpoint.

### P2 - Start scheduled raids at the source round boundary

Correction: consume the existing round-transition message and accept one eligibility decision per boundary, preserving source force/debug paths only where intentionally supported. Confidence high; current.
