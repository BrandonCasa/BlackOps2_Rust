## P3 - Re-shooting an already-playing key can incorrectly reset a rejected chord

- Original code: `src/staff_puzzles.rs:44-46,52`.
- Reference: `todo-audit-20261010/decompiled/t6/zm_tomb_quest_elec.gsc:190-213` blocks each active key's handler on `piano_keys_stop`. After an incorrect three-key chord, only a different, inactive key can enter the handler and clear the existing three notes (`:200-201`).
- Trigger: play an incorrect three-key set and then shoot one of those same three keys again.
- Actual behavior and impact: `notes.len() >= 3` clears the whole set before checking whether the hit key is already active. The old key becomes the first note of a new attempt and requests another sound. The reference ignores that repeated active-key hit, retaining the rejected set until an inactive key is hit. This changes how players recover from mistakes and how repeated shots affect the active notes.
- Future correction: retain per-key active state and ignore hits on active keys until the shared stop/reset signal; clear a rejected chord only when a new inactive key begins the next attempt.
- Status: outstanding at the bounded tip, `b9af42289:src/staff_puzzles.rs:79-87`.
