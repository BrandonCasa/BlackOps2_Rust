### 3. [P2] The same eligible sound changes from dry to wet solely because its cache is warm

- Draft: `src/audio.rs:533-544`; integration: `src/audio/decoded.rs:163-188`, `:231-249`.
- Reference: `environment-audit-20261010/decompiled/t6/zm_tomb_amb.csc:12-35`, `:58-84`; `audio-recovery/zm_tomb/soundbank/zmb_tomb.all.aliases.csv:1` has independent `Storage`, `ReverbSend`, panning and wet-distance fields.
- For a short clip's first request, `ClipCache::clip` returns its asynchronously loading handle immediately. `decoded_assets.get` is then absent, so playback is permanently created as a plain `DecodedClip`; it is not converted when decoding completes. A later request to the same warmed sound becomes a `RoomClip`, and eviction changes it back to dry again on a subsequent miss. Sounds over ten seconds and looping sounds always bypass the room path. Room acoustics therefore depend on cache history and clip length rather than the active room plus native send. The original message explicitly discloses the cold/streaming limitation, but it still prevents this implementation from reproducing consistent source room behavior.
- Future correction: apply room routing after an eligible source is ready, or share a processing stage that works with both cached and streaming decoders. Make the first use, repeated use and cache eviction acoustically consistent; handle native loop/stream sends without forcing full long-clip PCM residency. This does not require changing the locked engine or inventing assets.

### 4. [P2] Reverb tails extend character speech ownership beyond the dialogue duration

- Draft: `src/audio/reverb.rs:30-36`, `:42`; integration: `src/audio.rs:377-384`, `:438-449`, `:522-524`, `src/audio/narrative.rs:35`.
- Reference: `todo-audit-20261010/decompiled/t6/zm_tomb_vo.gsc:1100-1105`, `:1426-1431`, `:1574-1579`, `:1046-1048`; `audio-recovery/en_zm_tomb/soundbank/zmb_tomb.english.aliases.csv:1515-1516` illustrates the 90-priority source character voice metadata.
- Every cached eligible spatial dialogue decoder now emits an extra two seconds of samples and uses `PlaybackMode::Despawn` only after that tail. Its `PlayingSound` remains counted as active character speech for those two seconds. A new equal-priority character line is therefore rejected during an otherwise completed line's reverb tail; the narrative queue waits only the alias's original duration plus one second and then permanently pops the next line. This adds a warm-cache-only speech suppression window on top of the earlier queue/cooldown defect. Source conversations wait for the dialogue's sound completion and then use their scripted gap; they do not express an extra two-second ownership extension in the voice sequence.
- Future correction: separate dry dialogue completion/conversation ownership from an acoustic tail's playback entity, or acknowledge the actual speech completion explicitly. Preserve audible tails without retaining the old speaker's priority lock through them. This is a code lifecycle mismatch; exact native tail topology/duration remains unresolved.
