# Asset preparation and runtime import

The user permits necessary file types and raw inputs in this local-only repository. The complete installed texture/model source library is retained under `assets/source/bo2/`: untouched containers, decoded exchanges with native mips, lossless canonical masters and compressed PBR variants. Research captures and disposable tooling remain external. Keep optional source inputs separate from the validated runtime closure under `assets/origins/`. Keep `game.json` in ordinary Git and substantial binary assets in Git LFS. Originals remain untouched. Only ignored local configuration contains installation/output paths. The tracked template has placeholders. The importer accepts canonical surface metadata with DX10 DDS alongside standard glTF, PNG scaffolding and the existing audio/gameplay closure.

One command prepares the game pack: `uv run tools/prepare_origins.py --config config/local_assets.toml`. It reads the retained complete world exchange, material/image metadata, packed corner/UV streams, source map entities and OAT model exports. Missing entity/model exports are prepared through external OAT. Missing static placement metadata is exported by a read-only callback compiled against the existing external OAT x86 build.

Prerequisites: licensed Origins installation, the previously prepared external `full-scene-assets/texture-preview.json` and its referenced files, OAT v0.33.0, and the external OAT source/build when placement metadata is absent. Optional `[preparation]` overrides are `scene`, `entities`, `models`, `instances`, `unlinker` and `oat_source`. The converter currently consumes the retained world exchange rather than decoding fastfiles in Rust.

`uv run tools/prepare_origins.py --config config/local_assets.toml --prepare-triggers` adds the complete authored trigger catalog to `environment.triggers` in an external pack. It reads map entities and the retained clip-submodel brush closure (`preparation.trigger_models` may override that input; `trigger_receipt` selects an external receipt). Origins has 212 entries across seven classes, 519 convex brush/box pieces and one radius cylinder. Source names, flags and script fields remain attached to stable identities, including disambiguation of repeated GUIDs. Native `_zm_unitrigger.gsc::build_trigger_from_unitrigger_stub` supplies box/radius dimensions and angles; its debug geometry places boxes around their origin and radius heights above it. Brush intersections retain the existing 0.01 source-unit tolerance. Avian admits compound shapes as query sensors on their own layer; gameplay consumers select their source fields. Engine touch tolerances and script callbacks remain separate gameplay work. Mud preparation preserves this catalog, and mud/navigation/door converters share its native brush-vertex solver.

A read-only OAT callback recovers `GfxBrushModel.startSurfIndex/surfaceCount` ownership, with a matching 265-entry clip-model table. `preparation.brush_models` can select that retained external ownership table and `brush_receipt` selects the receipt. Canonical vertex attributes, material indexes and texture/mip bytes are preserved. Bounds, 78 convex hulls, local origins/rotations, original script fields and disambiguated identities remain available to consumers. Empty native hull sets stay empty, including helicopter volumes; bounds are retained without inventing solids.

Bevy loads these roots in the existing map scene and binds them to the brush catalog. Avian supplies isolated query geometry; existing door gameplay keeps its own removable blockers. Source `run_gramophone_door` moves the chamber brush down 260 native units and then deletes it, while `traversal_blocker` deletes its brush after the No Man's Land flag. This milestone supplies independent geometry/identity for those consumers; it does not implement their remaining quest, visibility, movement or collision rules. Convex reconstruction retains the existing 0.01 source-unit tolerance. Repeating the CLI on an unchanged prepared pack validates its bindings without changing bytes. Changed source inputs require preparing again from an external map pack whose brush surfaces have not yet been separated.

`uv run tools/prepare_origins.py --config config/local_assets.toml --prepare-traversal-links` extracts all 276 directed negotiation links from the compiled `PathData` table, preserving the existing 2,776 nodes/23,197 links and their stable ordinals. The read-only OAT callback retains begin/end types 17/18, spawn flags, source names/targets, authored positions, yaw/forward, radius, minimum-use distance and overlap indexes. `preparation.navigation` selects a retained external table; the default richer export lives under `solo-content/traversal-links-recovery`. `traversal_scripts` selects recovered GSC sources and `traversal_links_receipt` selects an external receipt. Legacy tables without endpoint constants require a fresh callback export. The ordinary navigation preparer uses the same conversion. This focused command preserves barrier zone overrides, blocker requirements and every actor/geometry/texture/audio file.

The compiled negotiation cost is 15 native units for every link, converted to 0.381 meters and consumed by the existing route solver. Link flags (0/8) and disconnect counts remain attached; source nonzero disconnects disable that route, though Origins' recovered counts are all zero. Unknown flag-bit behavior is not invented. All 23 source aliases must resolve to existing actor profiles and recovered scripts. Up/down/across jumps classify as jumps, including the 31 upward links formerly labelled climbs. `traverse/zm_shared.gsc::dotraverse` faces the start-node angle and selects noclip/nogravity; playback now uses that authored yaw. Fifteen source headings differ from endpoint direction by more than one degree. Avian projection/admission, fitted root curves and landing correction remain practical reconstruction; ordinary walking route weights, exact native engine arithmetic and scripted height overrides remain outside this extraction milestone. Actual-window receipts distinguish all retained links from geometry-admitted/access-enabled links and observe heading during playback and closure after restart.

`uv run tools/prepare_origins.py --config config/local_assets.toml --prepare-locomotion` runs after full rig/barrier/traversal preparation, reads Origins' native `animstatedefs/zm_tomb_basic.asd` and appends the missing XAnim tracks to the eleven prepared zombie body/head rigs. The default read-only OAT recovery loads common/patch dependencies before the map; `preparation.locomotion_asd` can select an already recovered external definition. All nine movement states retain their authored substate order and duplicates, including the second walk_v9 entry. The 28 distinct source clips now resolve on every compatible rig: 25 additions per rig, 275 new bindings and 66 total clips per rig. Existing binary prefixes, accessor/view/clip indexes, skins, meshes, materials and texture/mip files are preserved. Repeating preparation changes no bytes. Native notifications and source hashes remain available in the external preparation receipt.

The shared actor converter now exposes an append operation with the same coordinate/bind/channel rules used by ordinary conversion. Gameplay owns translation, retaining existing gait speeds and collider behavior. Intact walk/run/sprint select native variants with a stable per-actor seed, shared by torso and attached head. This reconstructs opaque engine substate randomness; it does not reproduce native RNG or speed matching. Crawl, stumpy and super-sprint clips are prepared data pending their gameplay consumers. No procedural fallback is needed for these recovered rigs.

World exchange: BO2DGS v1 has a 64-byte header, float32 XYZ positions, u32 triangle indexes and ordered 48-byte surface ranges. Corner prefixes are 36 bytes, containing position, color, packed UV/normal/tangent and lightmap UV fields. Secondary-corner metadata, local indexes and streams supply half-float layer UVs and signed normal-basis rotations. Geometry hashes, correspondence, bounds, finite values and complete ordered partitions are checked. Four custom glTF attributes carry layers/bases to Bevy. World triangles reverse to standard CCW together with every corner attribute. Geometry is independent of captured draw lists.

Outputs: external `map.gltf`, `map.bin`, PNG textures, `game.json` and `preparation.json`; import commits the complete runtime closure under `assets/origins/`. The glTF contains render and collision scenes. All 6,469 source surfaces are retained: 6,369 static world surfaces and 100 authored brush surfaces after brush conversion. Shadow helpers are hidden collision geometry. Static providers are shared across all 14,480 source placements. Source tangents and handedness, RGBA vertex colors, base UV seams and world secondary UVs survive preparation. Realtime cell grouping includes material and spatial cell only.

Material names preserve source identity. Version-two `material.extras.surface` declares pack-relative DDS URIs, roles, channel meanings, color space, native samplers, layer assignments, physical class and provenance. Native bindings distinguish packed gloss from coverage. The inspected gloss model initializes a GGX lobe approximation with `n = 2^(13g)` and perceptual roughness `(2/(n+2))^(1/4)`. Native RG slope normals become canonical tangent-space unit XY, with Y converted once. Explicit catalogs in `config/origins-materials.json` and `config/bo2-materials.json` supply editable physical presets; new identities use heuristic classifications recorded as approximations. Exposed metals are conductive; paint and rust remain dielectric. Normal detail and chromatic rust masks tune response without inverting albedo brightness.

`tools/prepare_materials.py` cooks the complete existing game pack from retained native DDS/material definitions. DirectXTex may2026 texconv is pinned by SHA-256. Base color/emissive use BC7 sRGB, normals BC5 linear, ORM/control BC7 linear and coating/scalar masks BC4 linear. Transformed mips use linear-light color, cutout coverage, normalized normals and normal-variance-aware roughness. Every compressed mip is compared with its lossless master; excessive error retains RGBA8 DDS. Native sizes remain unchanged. Optional source precision cubes/volumes remain untouched; they are excluded from the game closure. DDS is referenced through application metadata, outside standard glTF image arrays. A valid neutral PNG fallback asks Bevy to generate MikkTSpace tangents for tangentless rigs; prepared DDS replaces that fallback before rendering.

Native `document.extras.lighting`, node/mesh lighting assignments, SH, per-instance color accessors and probe faces are retired. Preparation keeps a `static_instance` marker for placement classification, exports no lightmap UV/color streams, and groups geometry independently of lighting. The runtime importer rejects baked metadata; original native values remain read-only research/source inputs.

The existing read-only OAT callback also emits external `model-surfaces.json` and richer placement metadata, including source model tangent/sign/color and all material image bindings, binding hashes and render state entries. Preparation refreshes exports lacking state records or `.surface-data-ready`. LOD0 surface/material/corner correspondence is checked against OAT glTF; unused material slots from other LODs are omitted. Retained world material inventory and recovered built-in texture definitions are checked by binding identity and image correspondence, not by assuming image-table indexes match.

Evidence: retained inventory/packed corners/lighting exports, OAT T6 packed-vector helpers and `GfxPackedVertex` definitions, and Git history's selected opaque response (`dbf869c`) establish the surface/channel and bitangent meanings. Retired renderer and shader implementations are not restored.

Limitations: per-family GGX fitting, material classification, reconstructed response masks, reveal constants and material masks are practical approximations. Native shader constants and original specular channels remain available for further refinement. Full-library preparation converts every declared model LOD and authored image, including unused assets. This coverage does not mean every material has received an artist review or every model was rendered in the game. Generated reflection targets have declarations and original fastfiles retained; they have no independent offline IWI payload.

The source `initial_spawn_points` entities supply the spawn-room anchor. `zone_start_spawners` and nearby path nodes supply practical enemy admission/pursuit. Dummy `info_player_start` is not the player spawn. Node projection replaces unimplemented climb/rise animations.

Preparation refuses repository output paths, escaped stream dependencies, malformed exchanges and missing required model textures. It never writes to original inputs. Preparation receipts may contain proprietary identifiers and remain external.

## Offline import and checkout

Prerequisites for import: Python 3.11+ through existing `uv`, NumPy 2 and Pillow 12 (script metadata resolves them), a complete external prepared pack, its complete dependency closure, and optional `preparation.json` for source reconciliation. Initial world assembly still uses retained world exchanges and OAT exports. No game process or network service is needed for validation once Python dependencies are cached. Preparation still relies on retained external world exchanges; this is not a complete fresh fastfile extraction command.

```powershell
git lfs install --local
uv run tools/prepare_origins.py --config config/local_assets.toml
uv run tools/import_origins.py --config config/local_assets.toml
uv run tools/import_origins.py --config config/local_assets.toml --check
```

Skip preparation when importing an existing prepared pack. The importer discovers `[game] asset_pack`, validates the entire supported prepared glTF profile before copying, preserves relative paths and shared mesh/placement references byte for byte, checks image decoding and rejects retired lighting metadata, and reconciles scene/texture/triangle counts. Retained source geometry verifies the original surface count; original placement metadata and model exports verify provider counts, placement order, reusable mesh references and transforms. Grouped runtime meshes alone cannot recover original surface/provider counts. Unknown glTF features fail closed. Source files are never modified. Replacing a pack retires obsolete files only after validating the complete previous closure. Unrelated files are rejected. Byte-identical dependencies are left intact. `--check` performs validation/hash comparison without copying. Optional `--receipt <external-file.json>` writes a hash manifest outside the repository and source pack.

The external receipt reports current texture/scene counts; realtime packs retain canonical PBR channels and no native probe faces. Source coverage remains 6,469 world surfaces, 149,907 world triangles, 14,480 static placements and 494 model providers. The importer checks source coverage, reusable references and transforms against current input data rather than relying on documented counts.

Tile/macro materials retain canonical repeating core/coating colors, detail normals, response layers and a control map. Runtime normalizes control weights and evaluates lighting through Bevy; no derived incident-darkness composite is exported. `surface.preparation` records the fourfold tiling reconstruction as `tile_macro_layers`. Original native bindings remain optional source data.

Weapon composition preparation uses `--recover-weapon-skeletons` and `--prepare-weapon-assemblies` on the same offline entrypoint. Apply `tools/oat-native-skeleton.patch` with `git apply --unidiff-zero` in the retained external OAT checkout, build its existing x86 Unlinker, and set ignored `preparation.native_unlinker` to that executable. Recovery reads base/shared/patch fastfiles into external `weapon-assembly/native-models`; assembly uses retained model/image/XAnim exports and the previously prepared full pack. Optional `preparation.weapon_assembly_output` selects another external evidence directory. The installed game has compiled assets and an executable, not a C/C++ source tree. The patched extractor retains native XModel.trans alongside baseMat-derived rest transforms. Absent animation channels retain rest; keyed translation adds the recovered native baseline before one unit conversion. Native attachment offsets apply once, declared sockets must resolve, skins/inverse binds are rebuilt, and hidden tags remove only exclusively influenced triangles. Variant/ADS compositions remain distinct; the external assembly report accounts for all definitions and records the four staff melee world-proxy exceptions. Import validates assembled skeletons, inverse binds and optional ADS dependencies with the complete existing closure. `origins.exe --verify-weapon-assemblies <external-output-folder>` surveys controlled native poses in the actual application; these captures qualify presentation, not absent acquisition or staff gameplay.

Scoped `.gitattributes` must be present before staging assets. Inspect candidates, run `git check-attr filter diff merge text -- assets/origins/map.gltf assets/origins/map.bin assets/origins/textures/model-0.png assets/origins/game.json`, inspect staged pointer contents with `git show :assets/origins/map.gltf`, then run `uv run tools/import_origins.py --config config/local_assets.toml --check-index` and `git lfs fsck`. The index check verifies every staged runtime filename, attribute, pointer hash/size and local LFS payload; it also compares the ordinary Git `game.json` blob against the source. Newline conversion is disabled for runtime bytes, including `game.json`. A new checkout needs Git LFS installed and `git lfs pull`; unresolved pointers are rejected by the importer. Local commits retain LFS objects locally; transferring a commit requires its LFS objects as well.

Playing uses `assets/origins/` beside `origins.exe`, or the repository pack when launched from its Cargo output directory. Discovery is independent of the working directory and reads no local configuration. Runtime overrides have been removed; `[game] asset_pack` remains an offline preparation/import setting.

`tools/build.ps1` packages `release/origins.exe` with `release/assets/origins/`. It calls the existing importer directly, validates the complete runtime closure, rejects unresolved LFS pointers/unrelated files, decodes PNGs, and compares all copied SHA-256 hashes. Packaging does not need originals, preparation receipts or machine-specific config; those source-reconciliation checks remain part of offline import. Copy the whole release directory to relocate the game. Missing dependencies produce loading errors in the game window/log with repair steps. Current real-window evidence is recorded in the handoff. Pack integrity and automated gameplay do not establish original-game equivalence.

## Complete installed library

Run sequentially with the ignored local config:

```powershell
uv run tools/bo2_library.py --config config/local_assets.toml
uv run tools/bo2_library.py --config config/local_assets.toml --packages
uv run tools/bo2_library.py --config config/local_assets.toml --retain
uv run tools/prepare_bo2_library.py --config config/local_assets.toml
uv run tools/prepare_bo2_library.py --config config/local_assets.toml --retune-unbound
uv run tools/bo2_library.py --config config/local_assets.toml --import
```

Read-only OAT callbacks retain material bindings/constants/states, samplers, technique identity, image hashes/dimensions and all model LOD declarations. Extraction covers every installed fastfile and every entry of each image package, including unreferenced entries. The library importer checks native declaration coverage, source hashes, model dependency closure, DDS dimensions/formats/transfers/mips and copied bytes before writing receipts. Original containers and decoded native exchanges live in `originals/`; canonical masters in `authoring/`; model LODs/material banks/compressed images in `converted/`. Large binary additions use LFS. These optional files are excluded from the shipped Origins pack.

GPU BC7 packed-response errors remain measured diagnostics for actual-window review, as requested by the user. Format, mip ownership, channel sampling and mask coverage checks remain enforced. The shared cache supports native cooking and legacy library callers; it does not replace rejected response encodes with lossless production assets. Current evidence and unresolved appearance qualification belong in the single handoff.

Texture upgrades use DeepBump's pinned `upscale256.onnx` exclusively. The density target is 2,048 texels/m everywhere. Density is `sqrt(sum(UV area in texels) / sum(surface area in meters))` for each material/mesh placement; the lowest placement governs a shared map. Actual ancestor transforms, nonuniform scale/shear, secondary layer UVs, intrinsic tile repeats and effect scales participate. UV slivers/degeneracy are counted separately, rather than using a nearly zero minor singular value as the area density. Constant material fields do not gain spatial detail from larger images and retain their exact values.

Each deficient map receives successive 4x DeepBump inference stages, then material-aware area reduction to the smallest sufficient power-of-two multiple of its source extent. The last stage can retain 2x by reducing each inferred 4x tile before storing it. Rectangular aspect ratios remain authored. Color mips filter in linear light, normals renormalize, response mips filter GGX alpha squared and packed scalar channels filter independently as linear data; normals interpolate authored slopes and responses interpolate GGX moments. Source alpha cells and the original lossless mip tail remain intact before block compression. Already sufficient maps skip inference but still receive the build-time compression recipe. The approved `--cap-to-device` policy limits edges to 16,384 and records every unmet target; omitting it rejects unattainable outputs. The target describes prepared material area density, not guaranteed density along every anisotropic UV direction, during every skin deformation, or in resident distant mips.

Run sequentially with external paths and the existing CUDA-enabled Python environment for inference:

```text
uv run --python '>=3.11' --with numpy --with pillow --with psutil --with soundfile python tools/prepare_texture_source.py assets/origins <external-source> <external-source-receipt.json>
uv run --python '>=3.11' --with numpy --with pillow --with psutil python tools/texture_inventory.py <external-source> <external-inventory.json> --minimum-density 2048 --close-density 2048 --cap-to-device
<cuda-python> tools/upscale_textures.py --pack <external-source> --inventory <external-inventory.json> --masters <canonical-masters> --model <upscale256.onnx> --device cuda --encoder <texconv.exe> --cache <external-compressed-cache> --output <external-candidates>
uv run --python '>=3.11' --with numpy --with pillow --with psutil --with soundfile python tools/prepare_upscaled_pack.py --source <external-source> --inventory <external-inventory.json> --masters <canonical-masters> --candidates <external-candidates> --destination <fresh-external-pack> --receipt <external-assembly.json>
```

Source recovery expands validated DDS bootstrap tails without changing meshes/content or modifying inputs. Inventory and candidate receipts support bounded `--select`/`--limit` batches and source/recipe/hash-qualified resume. Storage preflight rejects insufficient output space. Full assembly requires all candidate receipts, verifies the achieved densities/cap exceptions, exact source mip hashes, unchanged geometry/content and the complete importer closure. Inspect candidates before importing with the existing `import_pack` path. `--allow-partial` is only for an explicitly labeled qualification pack: its receipt and runtime index enumerate all pending maps, and it must not be described as a completed density migration.

Build-time compression uses the pinned DirectXTex encoder: BC7 sRGB color/emissive, BC7 linear packed fields, BC5 normal XY and BC4 coating. Constant and non-block-aligned tiny fields are explicit RGBA8 exceptions. Recipe five compares every actual final mip with its unchanged semantic master after any original compressed tail has been spliced. Generated/recompressed color has RMS <=0.025 and maximum error <=0.25; normals have RMS angular error <=2 degrees and maximum <=30. Existing same-format compressed source tails survive byte-for-byte with per-mip hash proof; their pre-existing codec errors are separately reported rather than altering original bytes. Other source tails are compressed and explicitly recorded as recompressed.

Inventory collects every actual masked material cutoff. New/recompressed masked color mips must preserve every pixel's coverage classification at all those cutoffs. BC7 alpha error weighting and bounded per-mip encoder margins repair only levels that fail classification; qualification still compares decoded output against the unchanged semantic master and the same numeric ceilings. Receipts record actual cutoff counts, flips and selected margins. Failed compression rejects the candidate instead of silently retaining a huge RGBA chain. Compression is lossy; these limits do not establish original appearance equivalence.

The external derived-data cache keys source/master hashes, DeepBump model, density/material recipe, encoder hash and target format. Cached bytes are verified on reuse. Candidates and assembly use hard links on the same volume; assembly moves the complete chain to its streaming URI and creates a fresh bootstrap file, avoiding duplicate full chains. Only compressed candidates persist; one temporary uncompressed mip chain is deleted after each cook. This follows [Epic's derived-data cache design](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-derived-data-cache-in-unreal-engine) and [DirectXTex's BCn options](https://github.com/microsoft/DirectXTex/wiki/Texconv). Inference defaults to CUDA, uses available GPU memory minus a 1 GiB reserve, maximum cuDNN workspace and fixed-buffer CUDA graph replay. CPU inference and compression can use all logical processors. Self-generated CPU/GPU utilization no longer pauses the cook; `--polite` restores resource-pressure yielding, and the shared actual-game/capture slot still takes priority. No reduced-precision model or changed DeepBump weights are used.

The version-two streaming index stores shared, local eight-meter triangle regions for each Bevy glTF primitive. Static camera/prefetch and alpha-shadow demand transform those bounds and use that region's sampling density, bounded by native 16x anisotropic filtering. Animated primitives use native posed bounds and their finest local map density so bind-pose cells cannot misrepresent current screen/shadow coverage. This prevents a complete world mesh's bounding sphere or a UV sliver from forcing full-resolution residency for distant surfaces. Stable Bevy Image IDs and the existing GI/reflection feedback still share mip ownership. Version-one packs retain their conservative fallback. This follows [Epic's UV-channel/scale and bounds guidance](https://dev.epicgames.com/documentation/en-us/unreal-engine/building-texture-streaming-data-in-unreal-engine) and [Microsoft's feedback discussion](https://devblogs.microsoft.com/directx/coming-to-directx-12-sampler-feedback-some-useful-once-hidden-data-unlocked/); [DeepBump's upstream implementation](https://github.com/HugoTini/DeepBump) is the model reference. Exact source appearance and neural detail fidelity still require actual-window inspection.

Selected material repair uses `repair_material_pack.py` after `prepare_texture_source.py`, followed by the same density inventory, semantic upscaler, compressed cache and `prepare_upscaled_pack.py` assembly used for every material. `material_semantics.py` resolves native binding hashes and channel meanings explicitly; unknown families, duplicate bindings, conflicting alpha meanings and missing declared UVs produce actionable errors. `config/origins-materials.json` owns physical recipes, including reviewed Mauser steel/wood and Dempsey leather/hardware masks. These are tunable physical reconstructions, not recovered native physical measurements. Authored normals and artwork remain the structural reference; no albedo shadows or baked occlusion are inferred. The retired four-set cook and separate streaming-only assembly paths are removed; streaming without upgrades uses the common assembler with `--allow-partial` and an empty candidate directory.

Native repair changes material maps and existing metadata only, preserving glTF declarations, geometry, skins, clips, gameplay and audio. Selected repair receipts remain external and explicitly label visual review pending. Compression/closure evidence cannot accept appearance: recreate the reference ground/water/wood, Mauser doorway and mixed-light interior views in the existing actual game, open every capture with multimodal viewing, inspect camera movement and write a judgment for each view before importing. Selected qualification is not the approximately 80 GiB bulk cook.
