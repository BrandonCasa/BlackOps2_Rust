# DX12 material batching investigation, 2026-10-10

The upload correction was committed first as `ce649c66800efe9c4a728e2f46699dacac9c5365`. This investigation uses Tracy to locate the remaining DX12 CPU overhead. Locked dependency versions, GPU culling, indirect validation, shader optimization, textures, lighting and shadows remain unchanged.

## Diagnostic evidence

Tracy 0.14.1 matches the locked tracy-client 0.19.0 / tracy-client-sys 0.30.0. The existing `tools/profile_rendering.ps1` collected CPU zones without elevation, with system tracing disabled. The profiling log filter now admits wgpu's info-level spans. The fixed view-8 survey is a CPU diagnostic workload, distinct from the combat acceptance benchmark. CPU zone durations include waiting and overlap across worker threads; their sum is not frame time or statistical CPU sampling.

The `dx12-upload-20261010-tracy` bundle and its DX12/Vulkan captures use the same source, scene, settings and tracing configuration. DX12 had 45 steady frame intervals over 7.770155 seconds; Vulkan had 160 over 7.967906 seconds. Per frame, DX12 issued 8,410 queue writes and about 5,687 bind-group creations; Vulkan issued 1,207 and 881. Command-encoder finish accumulated approximately 797.5 ms of elapsed time across DX12 worker threads per frame versus 67.3 ms on Vulkan. This does not imply a 797.5 ms frame.

The finer `dx12-encoding-20261010-tracy` capture attributed approximately 1,076 ms of aggregated elapsed time per frame to command encoding. Acquiring resource guards consumed only 0.047 ms. Native DX12 dispatch, begin/end encoding and compute-pipeline calls together consumed approximately 15.1 ms, despite 7,598 dispatches and 669 command encoders per frame. CPU-side processing of an amplified workload dominated these measured native calls. Winit event handling, surface acquisition and presentation did not account for the observed gap in these captures.

Source inspection found two independent reasons opaque materials fell back from bindless rendering on DX12:

- The material animation clock required a buffer binding array, unsupported by the pinned DX12 backend.
- The pinned Bevy derive macro counted individual texture and sampler fields against the sampler-array limit. The actual bindless layout shares one array per sampler kind. Multiple filtering samplers therefore incorrectly disabled bindless support at DX12's 2,048-element array limit.

## Correction

Vendor the already locked bevy_render_macros 0.20.0 and calculate sampler-array requirements from the distinct sampler kinds used by the generated layout. Retain capability checks and the existing material slab limits.

Move the animation clock into Bevy's existing shared globals uniform, extracting the same unwrapped `Time<Real>` value. This preserves animation while virtual time is paused without requiring a buffer binding array. Keep diagnostic mode in material parameter data, updated when the mode changes. Rust and shader layouts change together. No unsupported device feature is advertised.

Retain the focused profiling zones for future CPU investigations. Extend the external actual-game scenario with a required bindless-capability assertion and optional water-view captures. These are diagnostic checks, not an assertion that every material or every scene is correct.

## Matched unprofiled combat comparison

Use the existing `tools/benchmark_development.py`, with `WGPU_BACKEND` selecting each backend, the same pinned bundle, `--workload combat --repeats 3 --expected-resolution 2880 1620`. Runs are sequential. Each admits the same six durable enemies, warms up for at least 10 seconds after preparation/admission, and measures at least 30 seconds of complete main-world frame intervals. Seed 2818, workload revision 3, round 8, MG08, physical 2880x1620, TAA, resident KTX2 textures, native lighting/shadows, no vsync. Hardware: RTX 4080 16 GB, driver 616.92 / 32.0.16.1692, i7-12700KF with 20 logical CPUs.

GPU percentages are nvidia-smi samples restricted to each measured interval using the sampling-start log timestamp. Background CPU is the recorded top-20 background-process CPU-time delta over the entire run, including startup, divided by elapsed time and 20 logical CPUs. It is not a complete per-frame or per-core interference measurement. No overlapping game, capture or compiler was recorded in the accepted samples below.

This correction removes the major material-batching fallback and substantially improves DX12, but does not establish that DX12 beats Vulkan beyond run-to-run variation.
